# SerialHop CI/CD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the CI/CD design from `docs/superpowers/specs/2026-05-01-ci-design.md` — branch-protected `main`, PR-time test/lint/vuln/build gates, release-please-driven releases that publish a Windows binary + SHA-256 sums + Sigstore build-provenance attestation on every release-PR merge. Replace local auto-bumpversion with release-please as the single version-of-truth.

**Architecture:** Three GitHub Actions workflows (`pr.yml`, `release-please.yml`, `codeql.yml`) plus dependabot. Tooling changes turn `assets/manifest.xml` into a build-time-generated artifact (rendered from a committed `assets/manifest.template.xml` + the version in `assets/version.json`), which removes the need for release-please to ever touch `manifest.xml` and sidesteps the trailing-`.0` four-part-version problem. Everything else release-please updates is plain JSON.

**Tech Stack:** GitHub Actions; Go 1.25; Taskfile v3; release-please v4 (Google); golangci-lint v6; govulncheck; CodeQL; jq for build-time JSON reads; Sigstore / actions/attest-build-provenance.

```yaml
    types: [opened, synchronize, reopened, edited]

  group: pr-${{ github.event.pull_request.number }}
  cancel-in-progress: true

permissions:
  contents: read
  pull-requests: read

jobs:
  pr-title:
    name: Semantic Pull Request
    runs-on: ubuntu-latest
    steps:
      - uses: amannn/action-semantic-pull-request@v5
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        with:
          types: |
            feat
            fix
            chore
            docs
            refactor
            test
            perf
            build
            ci
            revert
          requireScope: false
          subjectPattern: ^.+$

  verify:
    name: verify
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-go@v5
        with:
          go-version-file: go.mod
          cache: true

      - name: gofmt
        run: |
          out=$(gofmt -l .)
          if [ -n "$out" ]; then
            echo "::error::Files need gofmt:"
            echo "$out"
            exit 1
          fi

      - name: go vet
        run: go vet ./...

      - name: golangci-lint
        uses: golangci/golangci-lint-action@v6
        with:
          version: latest

      - name: tests (race)
        run: go test -race -count=1 ./...

      - name: govulncheck
        uses: golang/govulncheck-action@v1

      - name: cross-compile windows binary
        run: |
          GOOS=windows GOARCH=amd64 go build \
            -trimpath \
            -ldflags="-H windowsgui -X 'github.com/bioexperiment-lab-devices/serialhop/internal/version.Version=ci-pr-${{ github.event.pull_request.number }}'" \
            -o /tmp/SerialHop.exe ./cmd/serialhop

      - name: upload artifact
        uses: actions/upload-artifact@v4
        with:
          name: SerialHop-pr-${{ github.event.pull_request.number }}.exe
          path: /tmp/SerialHop.exe
          retention-days: 7
```

### Task 4.2: Rewrite `Taskfile.yaml`

**Files:**
- Modify (full rewrite): `/Users/khamitovdr/lab_devices_client/Taskfile.yaml`

- [ ] **Step 1: Replace the file with the new content**

Write `Taskfile.yaml` with the following exact content:

```yaml
version: '3'

vars:
  GOOS: '{{.GOOS | default "windows"}}'
  GOARCH: '{{.GOARCH | default "amd64"}}'
  OUTPUT_DIR: dist
  BINARY_NAME: 'SerialHop{{if eq .GOOS "windows"}}.exe{{end}}'
  RESOURCE_FILE: cmd/serialhop/resource_windows.syso
  VERSION_PKG: github.com/bioexperiment-lab-devices/serialhop/internal/version

tasks:
  manifest:
    desc: Generate assets/manifest.xml from template using version from assets/version.json
    sources:
      - assets/manifest.template.xml
      - assets/version.json
    generates:
      - assets/manifest.xml
    cmds:
      - |
        VERSION=$(jq -r '.StringFileInfo.FileVersion' assets/version.json)
        sed "s/@@VERSION@@/${VERSION}.0/" assets/manifest.template.xml > assets/manifest.xml

  resource:
    desc: Compile the .syso resource (icon + UAC manifest + version metadata)
    deps: [manifest]
    cmds:
      - go run github.com/josephspurrier/goversioninfo/cmd/goversioninfo@latest
          -64
          -o {{.RESOURCE_FILE}}
          -icon=assets/icon.ico
          -manifest=assets/manifest.xml
          assets/version.json

  build:
    desc: Build the binary (override target via `task build GOOS=... GOARCH=...`)
    deps: [resource]
    cmds:
      - mkdir -p {{.OUTPUT_DIR}}
      - |
        VERSION_BASE=$(jq -r '.StringFileInfo.FileVersion' assets/version.json)
        VERSION_SUFFIX=$(git describe --tags --always --dirty --match='v*' 2>/dev/null || echo "unknown")
        VERSION="${VERSION_BASE}+${VERSION_SUFFIX}"
        GOOS={{.GOOS}} GOARCH={{.GOARCH}} go build \
          -trimpath \
          -ldflags="-H windowsgui -X '{{.VERSION_PKG}}.Version=${VERSION}'" \
          -o {{.OUTPUT_DIR}}/{{.BINARY_NAME}} ./cmd/serialhop

  test:
    desc: Run all unit tests
    cmds:
      - go test ./...

  tidy:
    desc: Tidy go.mod / go.sum
    cmds:
      - go mod tidy

  clean:
    desc: Remove build outputs and generated resources
    cmds:
      - rm -rf {{.OUTPUT_DIR}} {{.RESOURCE_FILE}} assets/manifest.xml
```

Key differences from the previous Taskfile:

### Task 5.3: Add `.github/workflows/release-please.yml`

**Files:**

- [ ] **Step 1: Write the file**

```yaml
name: release-please

on:
  push:
    branches: [main]

concurrency:
  group: release-please-main
  cancel-in-progress: false

permissions:
  contents: write
  pull-requests: write
  id-token: write
  attestations: write

jobs:
  release-please:
    name: release-please
    runs-on: ubuntu-latest
    outputs:
      release_created: ${{ steps.rp.outputs.release_created }}
      tag_name:        ${{ steps.rp.outputs.tag_name }}
    steps:
      - id: rp
        uses: googleapis/release-please-action@v4
        with:
          config-file: release-please-config.json
          manifest-file: .release-please-manifest.json

  release-build:
    name: release-build
    needs: release-please
    if: needs.release-please.outputs.release_created == 'true'
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v4
        with:
          ref: ${{ needs.release-please.outputs.tag_name }}

      - uses: actions/setup-go@v5
        with:
          go-version-file: go.mod
          cache: true

      - name: install Task
        uses: arduino/setup-task@v2
        with:
          version: 3.x
          repo-token: ${{ secrets.GITHUB_TOKEN }}

      - name: install jq
        run: choco install jq -y
        shell: pwsh

      - name: build
        run: task build
        shell: bash

      - name: rename and checksum
        shell: pwsh
        run: |
          $tag = "${{ needs.release-please.outputs.tag_name }}"
          Move-Item dist\SerialHop.exe "dist\SerialHop-$tag.exe"
          Get-FileHash -Algorithm SHA256 dist\*.exe | Format-List | Out-File -Encoding ascii dist\SHA256SUMS.txt

      - uses: actions/attest-build-provenance@v1
        with:
          subject-path: 'dist/SerialHop-*.exe'

      - name: upload to release
        shell: pwsh
        env:
          GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
        run: |
          $tag = "${{ needs.release-please.outputs.tag_name }}"
          gh release upload $tag dist/SerialHop-$tag.exe dist/SHA256SUMS.txt --clobber
```

Notes baked into this workflow:
- `release-please` job runs on every main push; outputs whether a tag was created and the tag name
- `release-build` runs only when a tag was created (i.e., the release PR was just merged)
- Windows runner uses bash for `task build` (mingw bash is preinstalled on `windows-latest`); pwsh for the rename/checksum/upload because path semantics are simpler
- `choco install jq` is needed because the `task build` step uses jq, and jq is **not** preinstalled on `windows-latest` (it is on `ubuntu-latest`/`macos-latest`)

## Failure-mode playbook

- **release-please opens a PR but the `assets/version.json` diff is empty.** A `jsonpath` typo. Inspect `release-please-config.json`. After fixing, push a no-op commit to `main` (e.g., a doc tweak); release-please will update the existing release PR.

- **`release-build` fails at `task build` on `windows-latest`.** The most likely cause is jq not on PATH (chocolatey installs it but the PATH refresh sometimes doesn't propagate to subsequent steps). Fix by adding `refreshenv` after `choco install`, or by replacing `choco install jq` with a direct download:
  ```yaml
  - name: install jq
    shell: pwsh
    run: |
      Invoke-WebRequest -Uri https://github.com/jqlang/jq/releases/latest/download/jq-windows-amd64.exe -OutFile C:\Windows\System32\jq.exe
  ```

- **`gh attestation verify` fails with "no attestations found"** for an actually-published binary. The `id-token: write` or `attestations: write` permission was missing from the workflow. Add them and re-run the failed `release-build` job (`gh run rerun <id> --failed`).

- **A bad release shipped (need to yank).**
  ```bash
  gh release delete vX.Y.Z --yes --cleanup-tag
  git revert <bad-commit>
  git push  # via PR
  ```
  release-please picks up the revert and proposes a new release.

- **release-please PR merges but no tag is created.** This usually means the previous release tag is missing or doesn't match `.release-please-manifest.json`. Verify `gh release list` shows `v0.3.0`; if it doesn't, create the tag manually one-time:
  ```bash
  git tag v0.3.0 <commit-of-version-bump-to-0.3.0>
  git push origin v0.3.0
  ```
  Then push a doc-only commit to main; release-please will reconcile.

## Self-review notes (recorded for posterity)

Spec coverage: every section of the spec (`pr.yml`, `release-please.yml`, `codeql.yml`, dependabot, .golangci.yml, tooling change, repo + branch settings, rollout sequencing, failure modes, verification checklist) maps to at least one task above.

Type / signature consistency: workflow file names, job names, status-check names (`verify`, `Semantic Pull Request`, `analyze`, `release-please`, `release-build`), config file paths (`release-please-config.json`, `.release-please-manifest.json`), and tag name format (`vX.Y.Z`) are used consistently across phases.

One deliberate deviation from the spec: the spec said "release-please updates `manifest.xml` via xml or generic updater (TBD in plan)." This plan resolves that by **moving `manifest.xml` out of release-please's scope entirely** — it becomes a build-time artifact rendered from a template + the version in `version.json` (which release-please does update). The decision is made and implemented in Phase 4. The spec's failure-mode entry about "XML updater can't write `${version}.0`" is therefore moot.
