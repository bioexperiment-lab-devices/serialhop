# SerialHop CI/CD design

**Status:** approved (brainstorm complete, ready for implementation plan)
**Date:** 2026-05-01

## Goal

Establish solid CI/CD for SerialHop such that:

1. `main` is protected from direct commits — code lands only via squash-merged PRs.
2. Every PR runs lint, vet, race-tested unit tests, vulnerability scanning, and a cross-compile build; all checks must be green before merge is enabled.
3. Releases are managed by [release-please](https://github.com/googleapis/release-please): main commits accumulate into a maintained release PR; merging that release PR tags `vX.Y.Z`, builds `SerialHop.exe` on a Windows runner, and publishes a GitHub Release with checksum + build-provenance attestation.
4. Releases are triggered manually by merging the release PR — no scheduled releases. Main is always release-ready, but does not auto-publish.

## Non-goals

- **Code signing** — Authenticode certificates ($200–400/yr) are out of scope. Defender false-positive workflow stays as documented in `README.md` (submit to Microsoft, restore from quarantine).
- **SBOM publication** — no downstream consumer currently asks for one.
- **CODEOWNERS** — solo maintainer; trivial to add later.
- **Signed Git commits on main** — deferrable.
- **Multi-platform release artifacts** — `SerialHop.exe` (windows/amd64) is the only published binary. Cross-compile is verified in CI for early-warning, not for distribution.

## High-level architecture

Three GitHub Actions workflows + one dependabot config + manual repo settings.

```
.github/
  workflows/
    pr.yml              # pull_request → tests + lint + cross-compile build (ubuntu-latest)
    release-please.yml  # push: main   → maintains release PR; on release-PR merge, tags + builds .exe (windows-latest)
    codeql.yml          # pull_request + push: main + weekly cron → SAST scan (ubuntu-latest)
  dependabot.yml        # weekly: gomod + github-actions
release-please-config.json
.release-please-manifest.json
.golangci.yml
```

### Event flows

**Normal PR push:** `pr.yml` runs. Status checks `verify` (build/test/lint/vuln) and `Semantic Pull Request` (PR-title format) must be green. CodeQL also runs but is not a required check.

**Push to main (squash-merged PR):** `release-please.yml` runs. release-please reads conventional commits since the last release tag and updates (or creates) a persistent "release PR" (default title pattern: `chore(main): release X.Y.Z`, configurable) containing version-file bumps + a regenerated `CHANGELOG.md`. **No tag is created and no artifact is built on a normal main push.**

**Release-PR merge (also a push to main):** `release-please.yml` runs again. release-please detects the merge of its own PR, creates the `vX.Y.Z` tag, and the workflow's `release-build` job runs on `windows-latest`, builds `SerialHop.exe` from the tagged commit, generates `SHA256SUMS.txt`, attests build provenance via Sigstore, and uploads everything to the GitHub Release that release-please already created.

## Component-by-component design

### 1. `pr.yml` — PR workflow

**Trigger:**
```yaml
on:
  pull_request:
    types: [opened, synchronize, reopened, edited]
concurrency:
  group: pr-${{ github.event.pull_request.number }}
  cancel-in-progress: true
```

`edited` is required so PR-title changes re-run the title check.

**Two parallel jobs:**

#### Job: `pr-title`
- `runs-on: ubuntu-latest`
- Single step: [`amannn/action-semantic-pull-request@v5`](https://github.com/amannn/action-semantic-pull-request)
- Allowed types: `feat, fix, chore, docs, refactor, test, perf, build, ci, revert`
- Scopes: any (no allow-list)
- Subject case: not enforced
- Surfaces a status check named `Semantic Pull Request`.

#### Job: `verify`
- `runs-on: ubuntu-latest`
- Steps:
  1. `actions/checkout@v4` (default depth is fine — full depth not needed for PR verification)
  2. `actions/setup-go@v5` with `go-version-file: go.mod`, `cache: true`
  3. `gofmt -l . | tee /dev/stderr | (! read)` — fails if any file would be reformatted
  4. `go vet ./...`
  5. `golangci/golangci-lint-action@v6` against `.golangci.yml` (linters: `errcheck, gosimple, staticcheck, unused, ineffassign, gosec`)
  6. `go test -race -count=1 ./...`
  7. `golang/govulncheck-action@v1`
  8. Cross-compile build verification:
     ```
     GOOS=windows GOARCH=amd64 go build \
       -trimpath \
       -ldflags="-H windowsgui -X 'github.com/bioexperiment-lab-devices/serialhop/internal/version.Version=ci-pr-${{ github.event.pull_request.number }}'" \
       -o /tmp/SerialHop.exe ./cmd/serialhop
     ```
     This skips `goversioninfo` resource generation — purpose is "linker is happy," not artifact production.
  9. `actions/upload-artifact@v4` for `/tmp/SerialHop.exe` with 7-day retention. Lets reviewers download a PR build for ad-hoc testing.

**Status check name for branch protection:** `verify`.

### 2. `release-please.yml` — release workflow

**Trigger:**
```yaml
on:
  push:
    branches: [main]
concurrency:
  group: release-please-main
  cancel-in-progress: false   # don't abort an in-progress release build
```

**Permissions:**
```yaml
permissions:
  contents: write          # create tags, push CHANGELOG.md, push release-PR branch
  pull-requests: write     # create/update release PR
  id-token: write          # Sigstore provenance attestation
  attestations: write      # build-provenance attestation upload
```

**Two jobs:**

#### Job: `release-please`
Runs on every main push.

```yaml
release-please:
  runs-on: ubuntu-latest
  outputs:
    release_created: ${{ steps.rp.outputs.release_created }}
    tag_name:        ${{ steps.rp.outputs.tag_name }}
  steps:
    - id: rp
      uses: googleapis/release-please-action@v4
      with:
        config-file: release-please-config.json
        manifest-file: .release-please-manifest.json
```

#### Job: `release-build`
Runs only when `release_created == 'true'`.

```yaml
release-build:
  needs: release-please
  if: needs.release-please.outputs.release_created == 'true'
  runs-on: windows-latest
  steps:
    - uses: actions/checkout@v4
      with:
        ref: ${{ needs.release-please.outputs.tag_name }}
    - uses: actions/setup-go@v5
      with:
        go-version-file: go.mod
        cache: true
    - uses: arduino/setup-task@v2
    - run: task build
    - run: |
        $tag = "${{ needs.release-please.outputs.tag_name }}"
        Move-Item dist\SerialHop.exe "dist\SerialHop-$tag.exe"
        Get-FileHash -Algorithm SHA256 dist\*.exe | Format-List > dist\SHA256SUMS.txt
      shell: pwsh
    - uses: actions/attest-build-provenance@v1
      with:
        subject-path: 'dist/SerialHop-*.exe'
    - run: gh release upload ${{ needs.release-please.outputs.tag_name }} dist/SerialHop-*.exe dist/SHA256SUMS.txt --clobber
      env:
        GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

**Invariant:** every published `.exe` is built from a tagged commit; the version inside the binary matches the tag name; the attestation proves it.

#### `release-please-config.json`

```json
{
  "release-type": "simple",
  "packages": {
    ".": {
      "package-name": "serialhop",
      "include-component-in-tag": false,
      "extra-files": [
        { "type": "json", "path": "assets/version.json", "jsonpath": "$.StringFileInfo.FileVersion" },
        { "type": "json", "path": "assets/version.json", "jsonpath": "$.StringFileInfo.ProductVersion" }
      ]
    }
  },
  "changelog-sections": [
    { "type": "feat",     "section": "Features"      },
    { "type": "fix",      "section": "Bug Fixes"     },
    { "type": "perf",     "section": "Performance"   },
    { "type": "revert",   "section": "Reverts"       },
    { "type": "chore",    "section": "Chores",       "hidden": true },
    { "type": "docs",     "section": "Documentation","hidden": true },
    { "type": "refactor", "section": "Refactoring",  "hidden": true },
    { "type": "test",     "section": "Tests",        "hidden": true },
    { "type": "build",    "section": "Build",        "hidden": true },
    { "type": "ci",       "section": "CI",           "hidden": true }
  ]
}
```

**`manifest.xml` is intentionally NOT in `extra-files`.** It is a build-time artifact rendered from `assets/manifest.template.xml` by `tools/render-manifest` (invoked from the `manifest:` task in `Taskfile.yaml`); the rendered file is gitignored. This sidesteps two release-please limitations: its built-in `xml` updater cannot write a `${version}.0` four-part Windows manifest version, and its `json` updater cannot write integer values. See section "Tooling changes" below for the rendering flow.

**`FixedFileInfo.{File,Product}Version.{Major,Minor,Patch}` are also NOT in `extra-files`.** release-please's `json` updater only writes string values; it cannot mutate the integer fields. These six integers are re-derived from `StringFileInfo.FileVersion` at build time inside the `release-build` job (a small `sync version.json integer fields` step that runs `jq` before `task build`). The committed `version.json` may carry stale integer fields between releases — that's by design; what matters is the binary's embedded VERSIONINFO, which is always current because the integer-sync step runs immediately before `goversioninfo` reads the file.

#### `.release-please-manifest.json`

```json
{ ".": "0.3.0" }
```

Tracks the current released version. release-please updates it on each release.

### 3. `codeql.yml` — SAST

Generated from GitHub's CodeQL starter for Go, trimmed:

```yaml
on:
  pull_request:
    paths: ['**.go', 'go.mod', 'go.sum']
  push:
    branches: [main]
    paths: ['**.go', 'go.mod', 'go.sum']
  schedule:
    - cron: '0 6 * * 1'

jobs:
  analyze:
    runs-on: ubuntu-latest
    permissions:
      security-events: write
      contents: read
    steps:
      - uses: actions/checkout@v4
      - uses: github/codeql-action/init@v3
        with: { languages: go }
      - uses: github/codeql-action/autobuild@v3
      - uses: github/codeql-action/analyze@v3
```

**Not a required status check.** Findings surface in `Security → Code scanning alerts`.

### 4. `.github/dependabot.yml`

```yaml
version: 2
updates:
  - package-ecosystem: gomod
    directory: "/"
    schedule:
      interval: weekly
      day: monday
    open-pull-requests-limit: 5
    commit-message:
      prefix: "chore(deps)"
  - package-ecosystem: github-actions
    directory: "/"
    schedule:
      interval: weekly
      day: monday
    open-pull-requests-limit: 5
    commit-message:
      prefix: "chore(ci)"
```

Dependabot PRs flow through `pr.yml`. The `chore(...)` prefix means release-please groups them as hidden chores in changelogs.

### 5. `.golangci.yml`

```yaml
run:
  timeout: 5m
linters:
  disable-all: true
  enable:
    - errcheck
    - gosimple
    - staticcheck
    - unused
    - ineffassign
    - gosec
issues:
  exclude-use-default: false
```

Default `gosec` rules; if specific rules trip on the chisel/winsvc paths during rollout, exceptions go through `nolint` directives next to the offending line, not in this config.

### 6. Tooling changes

#### Files removed
- `tools/bumpversion/` (entire directory; was the local auto-bump-on-dirty utility — release-please replaces it as the single source of truth)

(`tools/tools.go` stays — it pins indirect runtime dependencies in `go.mod`, unrelated to bumpversion.)

#### `Taskfile.yaml` updates

`bump:` task — deleted.

`resource:` task — drop `deps: [bump]`. Just runs `goversioninfo` against committed `assets/version.json`.

`build:` task — replace inline `VERSION=$(go run ./tools/bumpversion -print)` with:

```yaml
build:
  desc: Build the binary (override target via `task build GOOS=... GOARCH=...`)
  deps: [resource]
  cmds:
    - mkdir -p {{.OUTPUT_DIR}}
    - |
      VERSION_BASE=$(jq -r '.StringFileInfo.FileVersion' assets/version.json)
      VERSION_SUFFIX=$(git describe --tags --always --dirty --match='v*' 2>/dev/null || echo "unknown")
      VERSION="${VERSION_BASE}+${VERSION_SUFFIX}"
      GOOS={{.GOOS}} GOARCH={{.GOARCH}} go build \
        -trimpath \
        -ldflags="-H windowsgui -X '{{.VERSION_PKG}}.Version=${VERSION}'" \
        -o {{.OUTPUT_DIR}}/{{.BINARY_NAME}} ./cmd/serialhop
```

**Resulting `--version` strings:**

| Build context                          | Embedded `Version` string                  |
|----------------------------------------|--------------------------------------------|
| Local, on clean release tag            | `0.3.0+v0.3.0`                             |
| Local, between releases                | `0.3.0+v0.3.0-7-gabc1234`                  |
| Local, with uncommitted changes        | `0.3.0+v0.3.0-7-gabc1234-dirty`            |
| CI release on `vX.Y.Z` tag             | `0.4.0+v0.4.0`                             |

Windows VERSIONINFO (file-properties dialog) shows the un-suffixed `0.3.0.0` from `version.json` — OS-level metadata stays clean, only the binary's `--version` print carries the richer info.

`jq` is the version-file reader. It is preinstalled on all GitHub-hosted runners and on macOS Homebrew; the small dev-environment dependency is acceptable.

- Remove the paragraph documenting auto-bump-on-dirty behavior.
- Add a one-paragraph "Releases" section: "Releases are managed by release-please. PRs to `main` use conventional-commit titles. release-please maintains a `chore(main): release X.Y.Z` PR; merge it to publish a GitHub Release with the Windows binary, SHA-256 checksums, and build-provenance attestation."

## Rollout sequencing

Each step is a separate PR; the repo stays working at every step.

1. **PR 1: PR workflow + lint config + repo settings prep.** Add `pr.yml`, `.golangci.yml`. Flip squash-only / branch-deletion / workflow-permissions in repo settings. Branch protection not enabled yet (status checks need at least one green run before they can be marked required).
2. **PR 2: Enable branch protection on `main`.** No code change (or doc-only). Configure the protection rule in the UI to require `verify` and `Semantic Pull Request`.
3. **PR 3: Dependabot + CodeQL.** Add `dependabot.yml` and `codeql.yml`.
4. **PR 4: Tooling change.** Delete `tools/bumpversion/` (`tools/tools.go` stays — it pins indirect runtime deps). Update `Taskfile.yaml`. Update `README.md`. Verify locally: `task build` produces a binary; `--version` shows the new format; VERSIONINFO unchanged.
5. **PR 5: release-please.** Add `release-please.yml`, `release-please-config.json`, `.release-please-manifest.json`. On merge, release-please opens the first release PR aggregating commits since `v0.3.0`. Merging that release PR exercises the full pipeline end-to-end and produces the first artifact-bearing GitHub Release.

## Failure modes & recovery

- **Windows runner build flakes.** Workflow is idempotent at the tag level — re-running the failed `release-build` job rebuilds from the same tagged commit and re-uploads (the `--clobber` flag on `gh release upload` overwrites stale partials).
- **Bad release shipped (need to yank).** Delete the GitHub Release + its tag in the UI; revert the offending commit on `main`; release-please will pick up the revert and propose a new release.
- **release-please PR conflicts with a hand-edited `version.json`.** Don't hand-edit `version.json`; if it happens, close the conflicting release PR — release-please regenerates a fresh one on the next main push. (`assets/manifest.xml` cannot conflict because it's gitignored and regenerated from a template.)
- **release-please's PR doesn't fire `pr.yml` checks.** Known interaction: `pull_request` workflows don't trigger when the PR was created using `secrets.GITHUB_TOKEN` (GitHub's anti-recursion safeguard). Workaround: `gh pr close <N> && gh pr reopen <N>` — the reopen event fires the workflow normally. Long-term fix (deferred): switch `release-please-action` to use `actions/create-github-app-token`-minted credentials instead of `GITHUB_TOKEN`.

## Verification checklist (run after each rollout PR lands; final items confirmed after PR 5)

- [ ] PR workflow status checks gate merge on a sample PR.
- [ ] PR-title check fails on a non-conformant title and passes on `feat(scope): foo`.
- [ ] Direct push to `main` is rejected.
- [ ] Squash-merging a PR triggers `release-please.yml`; release PR appears.
- [ ] Release PR contains correct `version.json`, `manifest.xml`, and `CHANGELOG.md` updates.
- [ ] Merging the release PR creates a `vX.Y.Z` tag.
- [ ] `release-build` job runs on `windows-latest` and uploads `SerialHop-vX.Y.Z.exe` + `SHA256SUMS.txt` to the Release.
- [ ] `gh attestation verify SerialHop-vX.Y.Z.exe --owner bioexperiment-lab-devices` passes.
- [ ] Local `task build` on a clean working tree on tag `vX.Y.Z` produces a binary whose `--version` prints `X.Y.Z+vX.Y.Z`.
